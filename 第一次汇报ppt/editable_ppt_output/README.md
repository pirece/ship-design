制作日期：2026年11月2日。

本目录包含 **9 个同名单页 PPTX**、**1 个九页汇总 PPTX**、实际 PowerPoint 渲染图、逐页并排/叠加对照图、素材清单、生成代码和核验记录。原始 `ppt模板.pptx` 未改动。页眉、校徽、低多边形底纹、校门底纹和页脚沿用提供的模板。

## 打开文件

- 汇总文件：`pptx/combined_editable.pptx`。
- 单页文件：`pptx/原图片文件名_editable.pptx`。
- 逐页实际渲染：`previews/原图片文件名.png`；`previews/总览.png` 为缩略总览。
- 对照：`comparisons/*_并排.png` 左边原图、右边实际 PPTX 渲染；`*_叠加.png` 为两者各 50% 透明度叠加。
- 素材及例外：`asset_manifest.json`。
- 对象与文字核验：`acceptance_report.json`；单页实际打开检查：`single_file_checks.json`。

所有页面均为 **1672:941** 的原图比例，内部尺寸为 12192000 × 6861646 EMU，仅有整数坐标舍入误差。汇总和单页使用同一原生编辑树，没有把渲染结果回贴进 PPTX。

## 可编辑范围

主体包含 470 个原生文本框，标题、正文、编号、图注、坐标轴、图例、参数表和可辨读标注可直接编辑。模块框、标题栏、项目符号、圆环、时间轴、流程箭头、尺度线及简单图标均为原生形状或自由曲线。表格由原生背景单元格与文本组成；折线图由可编辑网格、轴标、点和折线组成，不是带电子表格数据源的 PowerPoint 图表。

为编号、条目、表格单元格和图标标签建立了可取消组合的小组。可以使用“选择窗格”定位 `标题_`、`模块_`、`图标_`、`组合_` 等命名对象。折线和箭头可编辑顶点，但没有将所有自由曲线端点绑定到节点，移动节点后需同时调整相应路径。进展页因圆环与各分区交叠，相关对象保持独立，以保持前后层级。

27 份照片、船舶渲染、主机渲染及工程图局部作为独立嵌入图片。它们可移动、缩放、裁剪、替换，**内部船体、结构、工程细线和像素不能逐个编辑**。这些局部素材均来自指定九张原图，没有调用生成模型、外部图片搜索或新增付费服务。参考原图只保存在源资料目录，未作为整页底图嵌入编辑页。

三维船体图片中的三处文字标注已从图片素材中排除，用原生文字、框体、引线及端点重新构建；没有生成或补造船体结构。进度规划页右下方的淡色船舶线稿经过色相分离，排除了周围正文。

## 明确保留的例外与视觉差异

1. **原图中不可辨读的工程小字未伪造。** 第9页右上“二维型线图”的站位编号、小表格、图签，第3页右上型线图及下方总布置工程图，第7页右下舱室工程图、右上彩色模型色标内的极小数值，保留在原始局部图像中，未转换为原生文本。这些是“全部文字原生可编辑”要求中尚未能完成的部分，需要清晰的原始工程图才能逐字还原。
2. 原图字体无法从位图确定。主体采用本机实际安装的 **Microsoft YaHei（微软雅黑）**；模板已有字体与标识保留。字体宽度、字重、字符间距与位图存在差异。没有分发系统字体文件。
3. 按用户要求沿用模板页眉页脚，所以红色、页脚线稿及背景纹理与部分参考图中的灰色变体不同。细部圆角、阴影、渐变、轮廓抗锯齿及局部标注转角为近似重建，不宣称逐像素一致。
4. 简单图标通过轮廓提取转成原生自由曲线，细小边缘有有限近似。第2页灰色俯视轮廓的舱口按原图位置重建。第6页淡色船舶线稿的极浅边缘可能减弱。
5. 第5页阻力/功率曲线、第7页阻力示意曲线和第3页稳性曲线按原图像素位置重描；没有把位图反算为新的实验数据，也没有重新计算性能。曲线采用有限顶点，局部弧度与原图略有差异；原图标注值与曲线位置之间可能存在不一致，均保留。
6. 原图疑似错误按原文保留。例如第1页第三行的“EEDI 和续航力计算仍十部分关键输入”，第一行措施中的“当前同版本静水力报告”；第7页与第3页的成员分工侧重点不同；第9页横剖面坐标轴中“0.5”等原样保留。没有擅自进行内容纠正。

## 源代码与重新生成

`source/scenes.json` 是按原图像素坐标组织的元素清单。`source/prepare.py` 保存全部文字、位置、颜色、局部裁切范围、图标轮廓及修正参数；`source/build.mjs` 创建原生对象；`source/package.py` 设置精确画幅、原生上下标、小组及单页文件；`source/finalize.mjs` 运行文件验证；`source/render.ps1` 和 `source/render_singles.ps1` 使用真实 PowerPoint 渲染；`source/audit.py` 生成核验记录和对照图。`source/reference_images/` 和 `source/template.pptx` 已包含重建所需输入。

实际环境：Windows、Microsoft PowerPoint COM、Python 3.13.0（Pillow 11.0.0、OpenCV 4.13.0、NumPy 2.1.3、lxml 6.0.2）、Codex 内置 Node.js 24.22.1 与 `@oai/artifact-tool` 2.8.106。Python 依赖版本见 `source/requirements.txt`。演示文稿验证器使用 Codex 自带 Python。没有将运行库、第三方包或字体复制进交付包。

在当前机器上可使用以下 Windows cmd 命令，自动写入新的 `pptx_rebuilt_时间戳` 目录，保留已有交付文件：

```cmd
powershell.exe -NoProfile -ExecutionPolicy Bypass ^
  -File "C:\Users\董昱彤\Desktop\船舶设计\第一次汇报ppt\editable_ppt_output\source\regenerate.ps1"
```

若迁移到其他机器，需在脚本中将 Node.js、Python、Codex 依赖目录与技能目录改为该机器的实际路径，并确认安装 PowerPoint 与上述字体。`source/node_modules` 只是本机依赖目录的联接，不随 ZIP 分发。
